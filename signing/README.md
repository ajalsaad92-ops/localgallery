# مفتاح توقيع التطبيق

`app-signing.keystore` هو مفتاح التوقيع الثابت للتطبيق.
**لا تحذفه ولا تستبدله** — أي تغيير فيه يجعل أندرويد يرفض تحديث النسخ المثبّتة
على أجهزة المستخدمين، ويضطرهم لحذف التطبيق وإعادة تثبيته (مع فقدان كل بياناتهم).

| | |
|---|---|
| الاسم المستعار (alias) | `androiddebugkey` |
| كلمة المرور | `android` |
| البصمة SHA-256 | انظر `FINGERPRINT.txt` |
| الصلاحية | حتى 2053 |

## لماذا المفتاح داخل المستودع؟

كان الوركفلو سابقاً يولّد مفتاحاً جديداً عندما لا يجد نسخة في الكاش، والكاش لم
يكن ينجو بين عمليات البناء — فخرج كل إصدار تقريباً بتوقيع مختلف، وصار زر
«تثبيت التحديث» داخل التطبيق يفشل دائماً.

تثبيت المفتاح داخل المستودع يزيل الاعتماد على الكاش وعلى أي إعداد خارجي:
نفس البصمة في كل بناء، إلى الأبد.

## الحد الأمني

المفتاح هنا مفتاح تطوير (debug) بكلمة مرور معروفة، والمستودع عام — أي أن أي
شخص يستطيع بناء APK يقبله أندرويد كتحديث لهذا التطبيق. هذا مقبول لتطبيق
يوزَّع عبر GitHub Releases عامة أصلاً، لكنه **غير مناسب** للنشر على Google Play.

للترقية إلى مفتاح خاص لاحقاً:

1. ولّد مفتاح إصدار حقيقي — **يجب أن تبقى كلمة المرور `android` والاسم
   المستعار `androiddebugkey`**، لأن Gradle وخطوة التحقق في الوركفلو
   يستخدمانهما بشكل ثابت. (لتغييرهما فعلياً يلزم تعديل `signingConfig` في
   `build.gradle` وخطوة `Verify signing fingerprint` معاً.)
2. حوّله إلى base64 وضعه في Secret باسم `ANDROID_KEYSTORE_BASE64`.
3. حدّث `FINGERPRINT.txt` ببصمة المفتاح الجديد.

## تنبيه مهم عن الـ Secret الحالي

يوجد على الأرجح Secret باسم `ANDROID_KEYSTORE_BASE64` في المستودع الآن، وهو
**تالف** (انظر التحليل في تقرير الفحص). إن لم تحذفه، ستفشل خطوة التحقق عمداً
مع رسالة واضحة بدل نشر APK يكسر التحديث. الحل: احذف الـ Secret.

الوركفلو يعطي الأولوية للـ Secret تلقائياً عند وجوده.
تنبيه: تغيير المفتاح يكسر التحديث **مرة واحدة** لمن ثبّت النسخة القديمة.
